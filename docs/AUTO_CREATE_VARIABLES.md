# Scriptで必要な変数・リストの自動作成

基準コミット: `732e0d4e7a465477168f595ae5d9313764ff8e14`  
開発ブランチ: `feature/auto-create-script-variables`  
確認日: 2026-11-12（日本時間）

## 生徒の操作

必要な拡張を追加し、Scriptを貼り付けて「検証」→「Scratchへ反映」→緑の旗で実行する。不足する変数・リストを先に手動作成する必要はない。

「検証」は作成予定の名前・個数と作成先を表示するだけで、VM、作品、既存値、リスト内容を変更しない。「Scratchへ反映」で初めてScratch VMのcreateVariableを使い、不足する変数・リストとブロックをまとめて反映する。確認ダイアログや新しい設定は追加しない。先生モードの自動反映は、従来どおり明示的に選択した場合だけ有効。

## 設計

- `native-scratch/references.js`: 参照解決と不足分の計画を、VMを変更しない独立処理にした。VMからworkspaceを読み込む間だけ、実在する参照IDを優先してBlocklyの公開作成APIを使い、同名資産が一方へ統合されることを防ぐ。グローバルなプロトタイプや資産名は変更しない。Scratchのdata系・control_for_each・メッセージの参照フィールドを扱い、普通の文字列、独自ブロック引数、拡張のラベルを変数扱いしない。
- `native-scratch/bridge.js`: workspace既定の変数IDを、新規コードのスコープ指定として誤使用しない。既存ブロックの有効な参照IDと、書き出したScriptの参照メタデータを保持する。名前を編集した場合は、以前の名前のIDを無条件で流用しない。
- `native-scratch/main.js`: 不足だけを理由とする生徒モードの拒否を廃止。プレビュー、反映、対象・作品変更後の再検証、Undoを接続した。反映とUndoの間はBlocklyのイベントを停止し、削除後に古い変数作成イベントで再作成されることを防ぐ。
- `native-scratch/safety.js`: 作成前の衝突再確認、作成と反映の一体化、失敗時の復元、安全なUndoを担当する。
- `native-scratch/lesson-tools.js`: AI用仕様JSONに、自動作成のタイミング・スコープ・曖昧さの扱いを追加した。文字数・ブロック数・未登録命令・メニュー等の既存制限は変更していない。

## 名前・種類・スコープ

1. 有効な既存IDがあれば、そのID・名前・種類が一致する参照先を使う。スプライト専用と全体用が同名でも、IDで特定できれば正しい方を再利用する。
2. IDで特定できない場合は、現在スプライトとステージにある同名・同種類の資産を調べる。一意なら再利用し、値・内容は初期化しない。
3. 同名・同種類が複数ある場合は、勝手にローカル／全体用のどちらかを選ばず、日本語でエラーにする。使いたいものを選んだブロックからScriptを取り出す。
4. 不足分は原則として現在スプライト用。ステージが対象なら全体用。メッセージは従来どおりステージに作成する。
5. 同じ名前の変数とリストは別種類として扱う。同じ名前・種類の複数参照は、作成予定を1件にまとめる。
6. 新しいIDは作品全体の既存IDとの衝突を避けて生成する。別のスプライト専用資産を指す明示IDは、現在対象へ勝手に結び直さない。
7. 日本語・英数字・通常の空白等は名前を変更せず保持する。空欄・空白だけの名前、改行・制御文字・不正な文字列はエラーにする。

書き出す `/*@scratch ...*/` に、必要な参照のid/name/typeを追加する。通常の手書き・AI生成コードにIDの記述は不要。既存コードの修正や.b2sの取り扱いでは、メタ情報を保持する。コピー先に元のIDがなくても、一意な参照先を再利用できる場合は再利用し、不足なら現在対象用に新しいIDで作る。

## 反映失敗・Undo

反映前に既存の自動保存を行い、保存できない場合は反映しない。検証後にコード・対象・作品の構造や変数名・種類が変わった場合も再検証を求める。

作成途中またはブロック反映が失敗した場合、反映前のブロック、既存変数・リストの値と内容、作成前の資産構成を復元する。作成途中でcreateVariableが例外を投げた場合も対象。復元自体が失敗した場合は成功と表示せず、「復旧」の利用を案内する。

Undoは今回の反映で新しく作った資産だけを対象とし、以前からあった資産を削除しない。戻したブロックと全ターゲットを確認し、他のスクリプトで参照されているもの、名前・種類が変更されたものは残す。sensing_ofの名前による読取も保守的に考慮する。

反映後に対象のブロックがさらに編集されていた場合は、後の編集を消すことを避けるためUndoを拒否し、保存・復旧を案内する。実行の途中状態や描画そのものを巻き戻す機能ではない。実行による通常の変数更新・リスト操作は従来どおり行う。

## 回帰に使った提示コード

SHA-256: `ef2c9fa1823a1398711e8e44de21226a948e5bc8b590fea92925a2e4f67e5dc5`

新規作品で、辺の長さ・x・y・色、およびxリスト・yリスト・長さリストが存在しない状態から開始した。検証時は作品が変わらず、プレビューは4変数・3リスト。反映後は92ブロックとなり、緑の旗で81回のペンダウン、実レンダラーへの243本の線描画、色カウンター162、空になった3つのスタックを確認した。

上記の単体42件とブラウザー7種類はすべて成功した。

結果JSON・スクリーンショット・保存作品の生成先は `stretch3-base/qa/auto-variables-*`、`auto-variable-safety-result.json` 等。テストは描画プリミティブを観測するが、実際のVM処理・ペンレンダラーを実行しており、模擬図形を生成したものではない。

既存の復旧テストでは、PoseNetの2つの非変数メニューについて、空の任意IDが未指定／nullに変わるだけの表現差を正規化した。実際の変数・リストID、選択値、作品全体の比較は維持する。復旧通知後のフィールドイベントが落ち着いてから容量不足試験を検証するようにした。

外部MLモデルの通信はこの実行環境で元の版でも失敗したため、復旧試験はモデル通信を保留してネットワーク・推論から分離した。3拡張の登録・ブロック・保存復元は実VMで確認するが、この試験はモデルのロード成功・推論精度・実カメラの品質を保証しない。

## 未確認事項・公開時の注意

- micro:bitの実機通信、実カメラ・実マイクによるAI認識、Chromebook実端末・40台規模は今回未検証。拡張命令の実機保証を追加したものではない。
- 属性名だけのsensing_ofや拡張独自データから、新しい変数や所有スプライトを推測して作ることはしない。対象は正式なScratchの変数・リスト参照フィールド。
- 構文・メニューの既存検査は維持するが、従来の検査が全引数型を網羅するという意味ではない。
- Scriptパネルの本番用ビルドは成功した。Stretch3本体を依存導入から再構築する完全なPagesビルドは、この環境では実行していない。READMEのNode 22と固定lockfileでCIを確認する。
- `native-scratch/build.mjs` の公開対応ソースにreferences.jsを追加し、既存Pagesワークフローのブラウザー検査へ新しい2試験を加えた。ホスティング設定や拡張本体は変更していない。
- mainへのマージで既存のPages公開ワークフローが動く。workflow_dispatchも公開処理を含むため、単なる事前テストとして実行しない。公開前の完全なビルド検証はローカルやデプロイを伴わないCIで行い、新規作品でのプレビュー・自動作成・保存も確認する。キャッシュや古いタブでは再読込する。
- 旧SHAを対象とする `gem-knowledge/` は本機能の実装とは別の履歴資料として保持した。公開後、Gemの「変数・リストを先に手動作成」の指示は「不足分は検証で確認し、反映時に自動作成」へ更新する。現在のAI仕様JSONにも自動作成方針が含まれる。
